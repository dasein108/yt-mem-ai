# SP0.5 — LanceDB Storage Migration + Semantic Search Design

**Date:** 2026-07-21
**Status:** Approved (brainstorming complete)
**Supersedes:** the SQLite storage layer from SP0 (`docs/superpowers/specs/2026-07-21-yt-summary-foundation-design.md`)

## Vision

Replace the SQLite store with a single embedded **LanceDB** store, and use its
native features — vector embeddings, full-text search (FTS), and hybrid
search + reranking — to add semantic search across the whole video library.
This aligns the code with the PRD's own tech stack ("Chroma or LanceDB") and
makes SP3 (recommendations) and SP5 (semantic highlights) native rather than
bolt-on.

## Why (and why now)

- SP0 shipped on SQLite; the store API is function-shaped and touches only 4
  source files, so migrating now — before SP1 discovery writes more code
  against the store — avoids a second migration later.
- LanceDB gives auto-embeddings on insert, FTS, and hybrid search out of the
  box. SP3's recommendation engine and SP5's semantic highlight selection both
  need vectors; having them from SP0.5 onward removes a whole future subsystem's
  worth of plumbing.

## Locked Decisions

| Concern | Choice |
|---|---|
| Store | **LanceDB only** (full replacement; drop `sqlite3`) |
| Embeddings backend | **Configurable**: `sentence-transformers` (local, default) or `openai`, via `YT_EMBEDDING_BACKEND` |
| New features in scope | semantic `search` command, chunk-level embeddings, FTS keyword search (+ hybrid) |
| Schema modeling | LanceDB `LanceModel` (pydantic) schemas |
| Embedding unit | `chunks` (merged ~30–60s windows), replacing raw `segments` |
| Old SQLite data | throwaway — fresh LanceDB start, no migration command |
| Sequencing | build SP0.5 before resuming SP1 |

## Tradeoffs Accepted

LanceDB is columnar/append-oriented with per-table atomic operations. Versus
SQLite we give up: foreign-key enforcement (now app-enforced) and multi-table
transactions (each table op is atomic on its own). For a single-user local tool
at this data volume these are non-issues; the ingest pipeline is already
resumable via `is_seen` keyed on the transcript row.

## Grounded API Facts (LanceDB, current docs)

- `db = lancedb.connect(path)`; `db.create_table(name, schema=Model, exist_ok=True)`; `db.open_table(name)`.
- Upsert: `table.merge_insert(key).when_matched_update_all().when_not_matched_insert_all().execute(rows)`.
- Update: `table.update(where="...", values={...})`. Delete: `table.delete("where")`. Count: `table.count_rows(filter=...)`.
- Metadata-only query: `table.search().where("...").limit(n).to_list()`.
- FTS: `table.create_fts_index("col", replace=True)` (native, no Tantivy dep).
- Vector/hybrid: `table.search(query, query_type="hybrid").rerank(reranker=...).limit(n).to_list()`.
- Auto-embedding: `get_registry().get(<backend>).create(name=<model>)`, then a `LanceModel` with `text: str = emb.SourceField()` and `vector: Vector(emb.ndims()) = emb.VectorField()` — text embeds on `add`.

## Architecture

```
yt_summary/
  config.py        + store_path, embedding_backend, embedding_model, chunk_target_s
  store/
    models.py      LanceModel schemas + chunk_model(embedder) factory
    embeddings.py  NEW: embedder factory (local|openai) + segment→chunk chunker
    db.py          LanceDB rewrite: connect/init_db/CRUD (merge_insert/update/delete)/search_chunks
  memory.py        is_seen/mark_status → LanceDB ops
  cli.py           show/status → LanceDB; run_fetch embeds chunks; NEW `search` command
  transcript/      unchanged (still emits Segment list)
skills/
  summarize-video/SKILL.md   rewritten to call CLI/JSON instead of raw SQL
```

### Data Model (LanceDB tables)

| Table | Key | Vector | FTS | Fields |
|---|---|---|---|---|
| `videos` | video_id | – | – | channel_id, title, url, duration_s, published_at, fetched_at, audio_path, status |
| `channels` | channel_id | – | – | title, subscribed |
| `transcripts` | video_id | – | `full_text` | source, lang, full_text, created_at |
| `chunks` | id | ✅ | `text` | video_id, start_s, end_s, text, vector |
| `summaries` | video_id | – | `summary_md` | summary_md, highlights(json), qa(json), model, created_at |
| `feedback` | (video_id, created_at) | – | – | signal |
| `app_state` | key | – | – | value |

`chunks` is the semantic core: per-chunk embedding + both a vector index and an
FTS index enable hybrid search with a reranker. Integrity (e.g. a `chunks` row's
`video_id` existing in `videos`) is app-enforced by the ingest order, not a FK.

### Chunking

Transcript providers still emit fine-grained `Segment`s. `store/embeddings.py`
merges consecutive segments into windows of ~`chunk_target_s` seconds (default
45s), concatenating text and spanning `start_s`..`end_s`. Chunks are the
embedding + search unit; highlight timestamps map to the nearest chunk
`start_s` (same approach the summarize skill already uses).

### Embeddings Layer

`store/embeddings.py`:
- `build_embedder(cfg)` → LanceDB embedding function from the registry:
  - `local`: `get_registry().get("sentence-transformers").create(name=cfg.embedding_model or "all-MiniLM-L6-v2")`
  - `openai`: `get_registry().get("openai").create(name=cfg.embedding_model or "text-embedding-3-small")` (uses `OPENAI_API_KEY`)
- `chunk_segments(segments, target_s) -> list[Chunk-dict]`.
- The embedder is **injectable** for tests: a deterministic fake `EmbeddingFunction`
  (fixed-dim hash vector, no model download, no network) is registered and used,
  so unit tests stay offline. One opt-in integration test exercises real
  `sentence-transformers`.

### Store API (`store/db.py`)

- `connect(store_path) -> lancedb.DBConnection`
- `init_db(db, embedder) -> None` — create all tables (`exist_ok=True`) and FTS/vector indexes.
- `upsert_video(db, v)`, `get_video(db, video_id) -> Video | None`, `list_videos(db) -> list[Video]`
- `upsert_channel(db, c)`
- `insert_transcript(db, t)` (merge_insert on video_id)
- `replace_chunks(db, video_id, chunks)` — delete existing chunks for video_id then add (idempotent re-ingest)
- `upsert_summary(db, s)`, `get_summary(db, video_id)`
- `insert_feedback(db, f)`
- `get_state(db, key) -> str | None`, `set_state(db, key, value)`
- `count_by_status(db) -> dict[str,int]`
- `search_chunks(db, query, k=10, mode="hybrid") -> list[ChunkHit]` — `mode` in {vector, fts, hybrid}; hybrid uses a reranker.

### CLI

Existing commands keep their surface; internals swap to LanceDB:
```
yt-ai fetch <url> [--force]      # now also chunks + embeds
yt-ai transcript <url>
yt-ai show <video_id> [--json]   # --json so the skill can consume it
yt-ai status
yt-ai search "<query>" [--hybrid|--fts|--vector] [-k N]   # NEW
```

### Error Handling

- Missing embedding backend deps / model download failure: clear error naming the backend; ingest of metadata+transcript can still succeed with chunk-embedding deferred (chunks written without vectors is NOT allowed — instead fail the embed step loudly and leave `status=transcribed` so a re-run retries embedding).
- `openai` backend without `OPENAI_API_KEY`: fail fast with an actionable message.
- LanceDB table-missing on first run: `init_db` is idempotent (`exist_ok=True`), run at connect.

### Testing

- Unit: store CRUD via a temp-dir LanceDB + fake embedder (offline): upsert/get/list, status update, idempotent `replace_chunks`, `merge_insert` update path, `search_chunks` returns expected ordering with the deterministic fake vectors, `get/set_state`, `count_by_status`.
- Chunker: segment→chunk merging windows and span math.
- memory: is_seen/mark_status against the new store.
- cli: `run_fetch` end-to-end with fakes writes video/transcript/chunks; `search` returns hits; `show --json` shape.
- Integration (opt-in, network): real sentence-transformers embed + hybrid search on one short video.
